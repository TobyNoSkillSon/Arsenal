# Native language worker

Arsenal owns the framed adapter, local-only tokenizer bridge, model-specific prompts/output parsing and schemas. No weight files are vendored.

The package keeps mlx-swift `901941965d82e4a216d4d117231d847d194c563d`, mlx-swift-lm `bd4b7434e6bdb588c7ef55706ff8904cb7fd4c57`, and swift-transformers `150169bfba0889c229a2ce7494cf8949f18e6906` unchanged. MLXVLM is linked explicitly. Local model and processor switches reference only G1 architectures and avoid the upstream global registries so unused architectures can be dead stripped.

- `Sources/LanguageWorker/Upstream/Hunyuan`: Hunyuan.swift and DynamicNTKAlphaRoPE from ml-explore/mlx-swift-lm `48114eedf3c3d4a682a6b1d644cc5af5c2945d10`. Adapted the LLMModel import and tied-head filter to the current pin. RoPE/qk-normalization ordering follows upstream. MIT, adjacent LICENSE-upstream.
- `Sources/LanguageWorker/Upstream/TeleOCR`: Qwen25VL.swift and QwenVL.swift from the pinned mlx-swift-lm. The maker's `XingChen-AGI/TeleOCR@70a19ec6a3b036311af19ae5e762e650f41a5980/modeling_naviocr.py` requires explicit head_dim, biasless text Q/K/V, Qwen3 Q/K RMSNorm and a stored output head. These differences are applied locally; the Qwen2.5 vision processor/tower remains. Small per-line lint annotations retain upstream arithmetic. MIT, adjacent LICENSE-upstream.
- `Sources/LanguageWorker/Upstream/LFM2VL`: LFM2VL.swift from the pinned mlx-swift-lm (MIT, adjacent LICENSE-upstream), types renamed `ArsenalLFM2VL*`. Following Transformers `modeling_siglip2.py`/`modeling_lfm2_vl.py` and mlx-vlm `lfm2_vl/vision.py`: the vision tower receives the pixel attention mask (padded thumbnail rows stay out of attention), position embeddings are resized with antialiased bilinear (`Siglip2PositionResize`) instead of bicubic, and an image-token/feature mismatch throws instead of fatalError. The pinned processor is dropped for `LFMVisionProcessor`.
- `Sources/LanguageWorker/Upstream/Gemma4`: the model half (configuration, text, vision, model; lines 1–2127, not the Unified variant or processor) of Gemma4.swift from the pinned mlx-swift-lm (MIT, adjacent LICENSE-upstream), split into three files under the 1,500-line limit, types renamed `ArsenalGemma4*`, file-private helpers made module-internal. Following Transformers `modeling_gemma4.py` and `image_processing_gemma4.py`: each image is encoded at its own aspect-preserving size (multiples of 48 px within 2,520 patches) from patches plus (x, y) position ids and yields (rows/3)·(columns/3) soft tokens (the pin forced 800×800, whose 50-patch side collides in the 3×3 pooler, and required exactly 280); the pooler averages by position and applies the sqrt(hidden) scale and standardization in float32; the patch projection's half dtype comes from the position table because int8/int4 tiers pack `input_proj`. Audio stays excluded. `GemmaVisionProcessor` replaces the pinned processor.
- `Sources/LanguageWorker/Upstream/Paddle`: configuration, graph, image processing and projector source from mlx-community/paddleocr-vl.swift `b31d5ab0bdb87a77ae80b74ec3380fed99f5b706`. Import/API and local type names adapted to the pin. MIT, adjacent LICENSE-upstream. Adapted to PaddlePaddle/PaddleOCR-VL-1.6 `c5630abae1d940eafe0697512a0325494b02ab42` reference: top-level ERNIE config and explicit head_dim; 3D sectioned RoPE; separate vision Q/K/V, patch/packing/learned position embeddings and pooling-head inventory; post-normalized vision features, 2×2 projector and maker preprocessing/template. All 620 checkpoint names/shapes match after the OIHW→OHWI patch-kernel map. Random modes and fixed-tensor RoPE/projector tests pass; trained fidelity is unqualified.

LanguageGraph normalizes Transformers 5 Qwen3-VL scalar EOS/rope spellings. For Gemma4 it removes unused K/V projections and K norm from KV-shared layers, which the pinned sanitizer already discards from the checkpoint. Gemma audio is never exposed. LFM's disabled projector LayerNorm is an explicitly recorded inactive source component, not silently selected at run time.

Maker prompt sources are pinned in the model folders. Model-local metadata is under `runners/native/` so the existing signed runner-closure inventory retains it. All lower-precision snapshots use IntegrationKit's streamed affine group-64 loader/converter. No networking occurs in a worker.

TeleOCR layout orchestration follows `caipeng328/NaviDC-OCR@1e71f4fe792d12bbb86d2671c5ed6f3a1499b27d/TeleOCR/vlm_utils/TeleOCR_client.py`: 1036-square layout input, normalized polygon/rectangle parsing, orientation-aware crops, block prompts and reassembly. Venus 1.5 grounding reference: `inclusionAI/UI-Venus@192a9247ad1129279ba1d6c263d4c9e7ecef3644`.

Output post-processing references (reimplemented, no code vendored): PaddleX `c852371c701d83cd21955b2963834825920ffebb` `paddlex/inference/pipelines/paddleocr_vl/{pipeline,uilts}.py` (OTSL tables, LaTeX delimiters, spotting location tokens); PrentisAI/GroundGUI `a1a02a93cb626b86c0ba829c38b613b8a40ecd0b` `eval/prompts.py` (per-platform `scalecua_toolcall` system prompts and tool-call coordinate parsing); inclusionAI/UI-Venus `1ffbaf653fb3d5d08e9ea14b013865496d68408e` `models/grounding/ui_venus2_gd.py` and `192a9247ad1129279ba1d6c263d4c9e7ecef3644` `models/grounding/ui_venus1_5_gd.py` (prompts and coordinate precedence); infly-ai/INF-MLLM `011866e93026290ba39f05b796c92d58dd0ce40c` `Infinity-Parser2/infinity_parser2/utils/utils.py` (JSON extraction, truncation recovery, Markdown fences); the pinned OvisOCR2 and NuExtract3 cards (figure crops, repeat cleanup, developer-message examples); NaviDC-OCR `TeleOCR/vlm_utils/TeleOCR_client.py` and `TeleOCR/src/vlm_middle_json_mkcontent.py` at the commit above (layout tolerance, crop preparation, Markdown rules).

Image processors (reimplemented, no code vendored): `QwenVisionProcessor` adapts the pinned `Qwen3VLProcessor.prepare` to Transformers `Qwen2VLImageProcessor` semantics (sRGB bytes, Pillow bicubic, Python-rounded smart_resize, folder pixel limits) and Chandra's `chandra/model/util.py` scale_to_fit and `chandra/input.py` image/PDF sizing (datalab-to/chandra, pinned in the model folder); `GemmaVisionProcessor` follows Transformers `image_processing_gemma4.py`/`processing_gemma4.py` (aspect-preserving resize, patches with position ids, `<|image>`/`<image|>` expansion with a per-image soft-token count); `LFMVisionProcessor` follows Transformers `image_processing_lfm2_vl.py`/`processing_lfm2_vl.py` (smart_resize, tiling with thumbnail, image start/end and row/column markers). `PILResample` reimplements Pillow 12 `src/libImaging/Resample.c` (8-bit fixed-point bicubic, Lanczos and bilinear with antialiased downscaling). `VisionActivation` sets each Qwen3-VL/Qwen3.5 vision block's GELU from `vision_config.hidden_act` (the pinned tower hard-codes the x·σ(1.702x) form).
