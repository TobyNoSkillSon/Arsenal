# Final picks, 2 Nov 2026

Runtime choice (AGENTS.md order): no bundled runner or MLX implementation of DiariZen exists; this is our own Swift port on the pinned mlx-swift with the maker's code as reference. Community-1 already ran pyannote's WeSpeaker ResNet34, the VBx PLDA (DiariZen's PLDA files are byte-identical to Community-1's) and VBx/AHC; those are reused. Community1Timeline gained frame geometry and speaker-count parameters (defaults unchanged), its Binarize frame centre now follows pyannote's arithmetic bit for bit, and its result builder gained an opt-in Python-style millisecond rounding; Community-1's tests stay green (default and heavy).

Weights: the maker's FP32 state dict (69.5M learned parameters; WavLM 63.1M, card says 63.3M) and the separately pinned WeSpeaker asset (6.6M). Get reads both in place (TorchCheckpoint learned pickle NEWOBJ for the Lightning checkpoint's dataclasses, kept opaque), folds the positional convolution's weight norm in Float32, and writes FP16 (152 MB). The pruned layers' remaining head indices are not in the checkpoint; they come from the maker's `wavlm_large_s80_md` configuration and Get checks their counts against the stored projections. FP16 passed every component bound, so BF16 was not needed.

Reference: the maker pins torch 2.1.1 for CUDA. On this Mac torch 2.1.1's MPS backend computes the WavLM feature extractor wrongly (CNN output max 3520 against 0.163 on torch 2.15 MPS and on a CPU check), predicting silence everywhere, so the reference ran the same maker code on torch 2.15 MPS (with a torchaudio shim for a removed type and a weights-only allowlist for the WeSpeaker checkpoint's pickled globals). The stepwise capture is asserted equal to DiariZenPipeline.__call__.

Bugs found and fixed during parity, each with a test: (1) the port applied the WavLM Transformer's layer norm to the hidden states; the maker builds that Transformer with `layer_norm_first = not layer_norm_first`, so extract_features never applies it. (2) A lint-driven `x += attention(...)` in mlx-swift updates the array object in place and rewrote the hidden state the caller had stored. (3) Millisecond rounding of half-millisecond frame centres differed from Python's round(). (4) The WeSpeaker checkpoint needed NEWOBJ in the pickle reader. (5) Segments of a clip shorter than its padded window outlasted the audio; they are now clipped.

Decision sensitivity: on the maker's AMI example VBx flips with embedding rounding alone. The maker's own pipeline with FP32 instead of FP16 embeddings differs from its FP16 run at 16.7% DER; the port is 21.0% from the FP16 run and 4.3% from the FP32-embedding run. The AMI gate is therefore min(DER vs either maker run) ≤ 16.7%, asserted on the unclipped segments; the three-voice fixture must match exactly and does. On the maker's own segmentation and embeddings the port's clustering and reconstruction reproduce the maker exactly (default tests).

Not checked: DER on a benchmark set, recordings longer than 30 s, five or more speakers, the app-level Get/Load through arsenal-testserver (it builds its QA catalog from committed folders and an allow-list), speed and memory figures (none claimed).

Review round (2 Nov, fresh Opus review: no port errors). Fixes, each with a test: parity now compares the unclipped segments (the maker's), and the served result is checked to equal them ended at the recording's length (a documented deviation: the maker's AMI example ends at 30.392 s of 30 s); files with more than two channels give channel 0 unmixed (NativeMedia cannot target more than two channels, so channel 0 is read and resampled on its own); the whole-file stage agreements are asserted (fixture exact, AMI at least 99%: bounds added after the first measurement, below it); a missing tolerance key fails the test; the PLDA-cache skip says why. The Community-1 frame-centre change is kept as pyannote-faithful and recorded in that model's log with its measured effect (JSON unchanged, RTTM durations move 1 ms in about 0.7% of segments). A ten-minute recording finished in 62.9 s through the worker, so the ten-minute limit stays. PLDA tables stay FP16 like Community-1's: the loader requires every stored tensor at 16-bit, and clustering reproduces the maker exactly with them.
