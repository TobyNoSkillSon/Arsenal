# FP16 Get

22 October 2026. Get stopped with "FP16 non-finite tensor: detector_model.text_encoder.text_projection.weight". A scan of all 1,961 FP32 tensors found exactly two values beyond FP16's 65,504: -9.58e18 at [6, 0] and [10, 0] of that tensor (every other value in it is under 0.2 in magnitude). It is CLIP's pooled-output projection, loaded but never used in SAM 3.1's forward (the detector projects the CLIP hidden states with `detector_model.text_projection`), so FP16 holds every tensor the model reads and BF16 is not needed.

Get first ran the family's generic half normalization, which casts every tensor and refused this one. The model recipe now reads the original file directly (as FLUX.2 and Stable Audio do) and drops the dead tensor; the loader also skips it if present.

Isolated Get (headless dev Arsenal, lab profile, source imported from a local copy): the FP16 snapshot is 1,745,596,328 bytes and loads 1,960 FP16 parameters. On a 512 × 512 zebra photo, a centre point prompt returned the whole zebra (score 1.0), but the text prompt "zebra" found nothing even at threshold 0.05: every FP16 text embedding was NaN. The CLIP padding mask multiplied -1e9, which is -inf in FP16, by zero for kept tokens. Building the mask in float32 fixed it: "zebra" returns one mask at 0.988 covering the animal. Both masks were inspected by eye. Vendor parity remains unrun; the detector neck still promotes some activations to float32.
