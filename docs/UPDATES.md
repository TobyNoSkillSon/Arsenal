# App updates

`ArsenalUpdateRepo` in `Contents/Info.plist` is `TobyNoSkillSon/Arsenal` in every build, the maintainer's own included; it comes from `Resources/Info.plist`, which also holds the version (`CFBundleShortVersionString`) and build number (`CFBundleVersion`, 2000 for 1.0.0 and one more per release). Nothing else sets them. A fork builds with `ARSENAL_UPDATE_REPO=` (empty), which drops the key; absent or empty means no scheduler, session or network request. Models and catalog ship together with the app; there are no separate model updates.

Releases are built and signed on the maintainer's Mac (`scripts/package-release.sh` with the release identity), tagged `vMAJOR.MINOR.PATCH` equal to `CFBundleShortVersionString`, and attached to a GitHub release with these assets; the maintainer then updates the tap's cask (`packaging/homebrew/arsenal.rb`) with the new version and SHA-256. `.github/workflows/release.yml` can do the same build in CI when started by hand on a tag, once the release-signing secrets are set. After each tag the next commit bumps both plist numbers, so later builds never share the released version.

- `Arsenal-MAJOR.MINOR.PATCH-arm64.zip`: a single top-level `Arsenal.app/`, made by `scripts/release-zip.sh` (`ditto -c -k --norsrc --noextattr --noqtn --noacl --keepParent`, so no `._*` entries). The bundle version matches the tag; `Contents/Helpers/ArsenalUpdateHelper` is present. Only `release.yml` builds and signs a release, with **Arsenal Release Signing** (SHA-1 `011C682945C225DBDEC95AEAA187BECBB0207282`); every signature's designated requirement is `identifier "<id>" and certificate leaf = H"011c682945c225dbdec95aeaa187becbb0207282"`. A locally packaged zip is never uploaded (`scripts/release-identity.sh for-upload`).
- `Arsenal-MAJOR.MINOR.PATCH-arm64-symbols.zip`: the unstripped binaries and their UUIDs, to symbolicate crash reports.
- `SHA256SUMS`: `shasum -a 256` lines (`<64 hex digits>  <file name>`) with a unique line for the app zip; it also lists the symbols zip. The zip is limited to 256 MiB. Only the relative native-worker aliases (`Helpers/arsenal-worker-<family>` → `arsenal-worker-native`) may be symbolic links.

Other ways in use the same zip and the same checks: `scripts/install.sh` (curl installer: SHA256SUMS, archive entries, version and the pinned certificate) and the Homebrew cask `tobynoskillson/tap/arsenal` (`auto_updates`, so Homebrew leaves updates to the app).

## Identity

The certificate is self-signed and not notarised; its key exists only in an offline backup and the GitHub environment `release-signing`, which only `v*` tags may use. The updater installs only a download that satisfies the installed app's designated requirement (`UpdateVerification.identity`, rechecked by the helper), so permissions such as Microphone and folder access carry over. An app signed with anything else (another certificate, ad hoc) never takes a release update; move it once with `scripts/install.sh --migrate-signing --allow-downgrade` or `brew install --cask`, after which macOS asks for Microphone and folder access once more.

Asset requests use ordinary binary HTTP negotiation; metadata uses GitHub JSON headers. Production asset/redirect hosts are limited to `github.com`, `api.github.com`, `release-assets.githubusercontent.com` and `objects.githubusercontent.com`, over HTTPS. Drafts and prerelease versions are ignored even if a release is mislabeled stable.

The OS schedules a background check about every three days while Arsenal runs. A persisted timestamp limits background attempts, including failures, to once per three days. An explicit manual “Check again” bypasses that limit and resets the background due time. A first due check is scheduled after about ten minutes. GitHub 404 means no published release yet.

The orange menu action downloads, verifies SHA256 and the installed designated signing requirement, then waits for the service's atomic idle gate. The helper waits for the app to exit, rechecks the signature, swaps the complete bundle, keeps `Arsenal.app.previous`, and relaunches with the saved loaded-model list. The swap uses one atomic `RENAME_SWAP`: `Arsenal.app` remains present even if the helper is killed, and its old bundle becomes `Arsenal.app.previous` at the same instant. Only failure to launch and answer the updater triggers rollback. A launched app gets thirty minutes to restore; model failures or a restore timeout keep the new app running and retain the previous bundle. At helper startup, UUID staging leftovers are reconciled without changing the installed bundle; a backup identified by bundle ID and version is recovered when an interrupted exchange left the incoming version at `.previous`. Pre-v3 or unverifiable backups are kept or moved aside, never deleted; leftover cleanup is best effort. Backup cleanup cannot prevent relaunch after a successful rollback exchange. Settings and model files stay in their existing support directory.

The app owner calls `try UpdateController.acknowledgeRelaunch(support: paths.support)` at the beginning of `LaunchDelegate.applicationDidFinishLaunching`, before awaiting `ServiceFactory.make`. This static receipt requires no controller, service or restore file. The owner then wires `UpdateServiceHooks`, calls `start()`, and calls `restoreAfterRelaunch()` after settings/service startup. `acquireIdle` drains work and blocks new requests atomically; `releaseIdle` reopens admission on a cancelled handoff. `restore` calls `await service.restoreAfterUpdate(ids: ids)` to preserve automatic residency and saved settings; public `load(id:)` would make every restored model manual. Model refusals are reported by the service; a thrown hook error is reported in the updated app. `quit` must defer AppKit termination outside the main-queue drain:

```swift
quit: {
    RunLoop.main.perform(inModes: [.default]) {
        MainActor.assumeIsolated { NSApp.terminate(nil) }
    }
}
```

A returning quit closure leaves the controller in `.installing`. The helper watches parent exit for 120 seconds (longer than the app's ten-second shutdown limit), then permits a further thirty seconds for a late exit before returning admission to a still-running parent. Launch and answering each have a sixty-second deadline. A missing launch callback first looks for an app running at the exact installed path. If no result can be confirmed, the helper retains the verified app, `.previous` and restore record and reports that result; it removes the superseded older backup, issues no second launch and does not race a possibly pending launch with rollback. A matching late launch receipt removes that token’s timeout notice. Restore acknowledgement is separate from launch acknowledgement; both updated and rolled-back launches consume their receipts. Restore cleanup checks the record’s token, and helper acknowledgement polling runs once per second. Background check errors preserve the last offer and expose `lastCheckFailure` for diagnostics; a requested manual check reports `.failed(reason:)`. Once the app answers, model/restore errors belong to that running app and the helper writes no later-startup failure notice. Late successful restoration tolerates helper cleanup of the restore file. The menu binds to observable `state` or `events()` and calls `installAvailableUpdate()`.

Local acceptance: `scripts/mlock work update-test -- python3 scripts/test-updates.py`. Its thirty cases use localhost, signed fixture apps and isolated installs under `/tmp`, with two fake model IDs. Two disposable certificates live in an explicitly selected temporary keychain; the user search list stays unchanged, and cleanup deletes the keychain. No real identity, login-keychain item or model data is used. The fixture compiles the actual AppDelegate quit path and compares the helper deadline with `AppDelegate.quitLimit`; constructor-only faults exercise recovery and timeouts. `--cases <comma-separated names>` bounds reruns; `--skip-idle` reuses unchanged scheduler evidence. This acceptance stays separate from `scripts/test.sh` because it invokes LaunchServices and creates a keychain; the unit suite also runs in noninteractive environments.
