Local adaptations: common Arsenal MLX pin; native adapter; no network/download path; streamed precision installation; bounded cancellation. Checkpoint mapping and source identity are in each model folder.

Additional adaptations: FP16 default; quantized SAM lookup tables use Embedding calls rather than raw packed storage; no unused DINO register parameter for Nano; decoder fused QKV stays one checkpoint-compatible Linear; LocateAnything uses the pinned tokenizer API and cancellation between bounded decoding steps. Tests use the exact same native adapter graphs.

CLIP BPE vocabulary and merges are not in the SAM 3.1 checkpoint. The model folder pins them as the `clip-bpe` asset, openai/clip-vit-base-patch32 at 3d74acf9a28c67741b2f4f2ea7635f0aaf6f0268 (`vocab.json`, `merges.txt`, MIT as in the upstream CLIP repository); the worker loads them from that verified folder. Byte-identical copies for no-download lab checks live in Workers/Perception/Tests/PerceptionTests/Fixtures/tokenizers/clip-bpe.

Checkpoint mapping: `Loading/OfficialCheckpoint.swift` is Arsenal contributors' Swift port of the key mapping in `mlx_vlm/models/sam3_1/convert_weights.py` from mlx-vlm 0.4.3 (https://github.com/Blaizzy/mlx-vlm, MIT, `LICENSE-mlx-vlm`), which converts Meta's `facebook/sam3.1` checkpoint `sam3.1_multiplex.pt`. Adaptations: it runs at Get on the verified file and reads it tensor by tensor through the shared non-executing PyTorch reader instead of `torch.load`; a second stage renames the result to the module names of the mlx-community/sam3.1-bf16 layout the port was written against (transformers-style SAM 3 names such as `o_proj`, `mlp.fc1`, `proj_in`/`proj_out`, `upscale_conv1`); ConvTranspose2d detection also covers the mask decoders' `output_upscaling`; CLIP's unused pooled-output projection is left out; the stored `config.json` drops the 0.5x FPN scale, for which the checkpoint has no weights.
