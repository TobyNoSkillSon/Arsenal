# Music native sources

Selected source: `arraypress/swift-music-generation@51034b9874a046d4fe6e092524f8daf0940309ef`, MIT. `LICENSE-upstream` and `THIRD_PARTY_NOTICES.md` retain its notices. Imported the YuE2 network, prompt/tokenizer/sampling/flow solver; ACE-Step turbo network, planner, text encoder, diffusion and finishing; and shared Oobleck, audio and request types. No application, CLI, style catalog, package graph, repository downloader, licence acceptance actor, external LoRA loader or remote inference path is imported. YuE generation's synchronous mathematical closure is extracted into `YuEGeneration.swift`.

The closure uses Arsenal's unchanged MLX `901941965d82e4a216d4d117231d847d194c563d`, MLX LM `bd4b7434e6bdb588c7ef55706ff8904cb7fd4c57` and transformers `150169bfba0889c229a2ce7494cf8949f18e6906` revisions. Adaptations cover the older tokenizer/Qwen APIs, typed throws, cancellation between native steps, streamed stored-tier loading, half parameters/activations and direct use of the current lyric Embedding module (including QuantizedEmbedding). Narrow lint exceptions preserve upstream math and avoid MLX alias-mutating shorthand assignments. The source's FP32 VAE compute and YuE BF16 transformer become FP16, except ACE-Step's lyric encoder, which computes in BF16, as upstream does, and returns FP16 because its trained residual stream passes FP16's range on real lyrics (`models/ace-step-1.5/log/004-bf16-lyric-encoder.md`); trained numerical and output fidelity remain unqualified.

`NativeConversion` callbacks own layout preparation. YuE's verified VAE asset is folded/transposed into a decoder-only canonical snapshot alongside the main transformer. ACE's nested DiT, VAE, planner, encoder, tokenizers and silence latent remain in one standalone snapshot; weight normalization and convolution layouts are prepared once. The bounded stored-ZIP reader remains only for the source silence tensor. Int8/int4 recursively derive from this prepared half snapshot using group-64 affine matrices; every eligible component participates. Canonical markers prevent a second layout transform. Exact source-to-native mappings live in each model's `gate/component-map.json`; synthetic conversion/reload tests use those mappings and an independent weight-normalization/permutation fixture.

Both adapters expose `generate_music` through the shared worker registry and existing async operation jobs. Default output is one WAV so the standard audio route can consume it; optional score/metadata and batches use the generic file result. All serving is native Swift/MLX. Header-only source inspection, random graph smokes and synthetic conversions establish wiring and shapes, not trained quality, performance or memory requirements.

MiniMax Music 3 (`Sources/MusicWorker/MiniMax/`) is Arsenal's own Swift MLX port following the maker's diffusers integration at `huggingface/diffusers@2da7040be1a2e5f2fcbc8b985083342a308f5a86` (`src/diffusers/modular_pipelines/minimax_music3/` and its MiniMax Music 3 model modules, "Copyright 2026 The MiniMax Team and The HuggingFace Team", Apache-2.0, `LICENSE-upstream-diffusers-Apache-2.0`): the prompt contract (`encoders.py`), the guided autoregressive frames, the windowed flow matching and the vocoder; the global language model follows transformers' Qwen3 (Apache-2.0). mlx-audio's Python MLX port was read for structure only. Modified by Arsenal: Swift/MLX, a trimmed sampling head, batched classifier-free guidance, float32 snake activation. The weights are under the MiniMax-Music3 Community License, downloaded on Get from `MiniMaxAI/MiniMax-Music3@1b525ccb`, whose LICENSE Get also fetches.
