# FLUX.2-dev VAE vs FLUX.2 klein 4B VAE for IDOL (2 Nov 2026)

IDOL's config names `black-forest-labs/FLUX.2-dev` (FLUX non-commercial licence) for its VAE and uses only the encoder,
loaded with `torch_dtype=bfloat16`. Arsenal uses `black-forest-labs/FLUX.2-klein-4B@e7b7dc27` `vae/` (Apache-2.0).

- Dev file: `Comfy-Org/Flux-2-Dev` `split_files/vae/flux2-vae.safetensors`, SHA-256 `d64f3a68…f9c4b5`, 336,213,556 bytes.
  It is byte-identical to Black Forest Labs' gated `vae/diffusion_pytorch_model.safetensors`: its hash rebuilds that
  file's Git LFS pointer id `1fd5b491…` exactly. Used only for this local test; nothing ships or is pinned from it.
- Klein file: Arsenal's snapshot, SHA-256 `ca70d220…0e04` (the official LFS id), 168,120,878 bytes.
- Tensors (`Workers/Geometry/scripts/idol_vae_tensors.py`): 251 and 251, same names and shapes; dev is FP32, klein
  BF16. After IDOL's own cast to BF16, all 251 are bit-identical (0 differ).
- Config: dev's `vae/config.json` (gated, 770 bytes, Git blob `183bd5fa…`) is rebuilt exactly from klein's by dropping
  `_name_or_path` and setting `_diffusers_version` to 0.36.0.dev0: every architecture field (channels, latent 32,
  batch-norm eps 1e-4, patch 2×2, quant convs) is the same.
- Encodes through idol-sdk's own `_flux2_tokens` (same seed, CPU, 256 px) on IDOL's gallery pictures: armchair and
  grandma give identical tokens (torch.equal). The third picture was stopped by the run's time limit; BF16
  convolutions on the CPU are slow, and the bit-identical weights already settle it.

Conclusion: with IDOL's BF16 cast the two encoders are the same function, so the image tokens, and therefore the
splats for a given seed, are identical. Klein is used.
