# Arsenal MCP

Arsenal hosts MCP inside the app on the existing loopback listener at `/mcp`. It uses the official Swift SDK 0.12.1 library, with a bounded replay buffer and stream cleanup patch recorded in `Packages/swift-sdk/PORTED-FROM.md` and Streamable HTTP: POST requests, GET SSE notifications, DELETE session termination, protocol negotiation and cancellation. A bearer token lives in `<support>/mcp-token` with owner-only permissions (0600). Every MCP request requires the token; Host must match the listener, and browser Origins are rejected. Sessions are separate from authentication.

The MCP server is the main way agents use Arsenal; the HTTP API stays for scripts. Tool results are text written for the agent to relay, not JSON dumps: clients that receive `structuredContent` hand the model that JSON instead of the text, so no tool declares an output schema and structured data is opt-in (`format:"json"`). The server's `instructions` tell an agent what Arsenal is for and the consent rule before it loads any tool. The tool prefix (`arsenal_`) and server name come from `MCPNames` in `Sources/ArsenalCore/Service/MCPNames.swift`.

## Connect

`GET /arsenal/v1/mcp/connect` returns token-free command templates, `url` and `token_path`. The loopback HTTP control API is trusted local access; browser requests are refused by Host/Origin checks.

Register the stdio bridge; it finds the app's port and token on every launch:

```sh
claude mcp add arsenal -- arsenal-mcp
codex mcp add arsenal -- arsenal-mcp
```

Without `arsenal-mcp` on your PATH, use the absolute path `/Applications/Arsenal.app/Contents/Helpers/arsenal-mcp` (or the `~/Applications` copy). HTTP clients register the endpoint instead, reading the private token from the support directory. The port is only preferred: when 8798 is taken Arsenal picks a free one, so read `status.json` again if the connection fails after a restart.

```sh
support="${ARSENAL_SUPPORT_DIR:-$HOME/Library/Application Support/Arsenal}"
port=$(python3 -c 'import json,sys; print(json.load(open(sys.argv[1]))["port"])' "$support/status.json")
export ARSENAL_MCP_TOKEN=$(cat "$support/mcp-token")
claude mcp add --transport http arsenal "http://127.0.0.1:$port/mcp" --header "Authorization: Bearer $ARSENAL_MCP_TOKEN"
codex mcp add arsenal --url "http://127.0.0.1:$port/mcp" --bearer-token-env-var ARSENAL_MCP_TOKEN
```

Keep the token private. The exported variable must be present when Codex starts. The bridge emits protocol messages only on stdout and diagnostics on stderr.

## Tools

Fifteen tools, in this fixed order. The list never changes as models are added; per-model inputs are data (`arsenal_model`, schema resources).

| Tool | Inputs | Does | Annotations |
|---|---|---|---|
| `arsenal_find` | `query?`, `task?`, `on_mac?` (`table`, `installed`, `loaded`), `language?`, `state?` (a model state such as `failed`), `runs_here?` (default true), `commercial?`, `limit?` (default 8), `format?` | Searches the catalog and the user's table by what each model does: a query word scores highest when it names an operation or task the model declares, directly or through everyday words ("invoice" → `read_document`, "button" → `ground_screen`), then name, languages, purpose, good-for, media, kind and summary; limits are not searched. When some model does what the query asks, only such models are listed, and hits under 70% of the best score are dropped rather than padding the list; nothing relevant answers `No model for "…"`. `task` takes an operation, task or kind name or everyday words for one ("speech to text", "ocr"); `language` takes a code or English name (`pl`, `pl-PL`, `Polish`) and also matches multilingual (`mul`) models, listed after those declaring the language. Ties: suggested, added and installed models first. Each hit: purpose, size, RAM need, state, good for, can't. Models over the memory limit are counted, not hidden silently. | read-only, idempotent |
| `arsenal_model` | `model`, `operation?`, `docs?`, `format?` | One model: licence, state per precision, RAM need against free memory, update/revision/approval notes, runners, good for and limits, each operation's input fields as lines, a `Run:` example and the schema URI. `docs:true` appends the README. | read-only, idempotent |
| `arsenal_status` | `history?`, `format?` | Memory against the limit, loaded models (footprint, busy or idle), running jobs and downloads (also ones started in the app), playback; `history:true` adds the last day's jobs and the last minute per model. | read-only |
| `arsenal_add` | `model` | Records a catalog model for the table. Downloads nothing: the table holds exactly the models with files on this Mac or a download under way, so a downloaded model is already there and one not downloaded joins it when its download starts (a consented run, load or download puts it there). | idempotent |
| `arsenal_remove` | `model` | Takes a model without files on this Mac (a failed download) off the table. A model with files is on the table because of them: remove refuses and points to `arsenal_delete` with `confirm:true`, which needs the user's yes. Refused while a job uses it. | idempotent |
| `arsenal_delete` | `model`, `dtype?`, `remove?`, `confirm?` | Without `confirm:true`, answers what would be deleted (each downloaded precision and its size) and deletes nothing. With it, deletes every downloaded precision, which takes the model off the table, or only `dtype`'s; `remove:true` also clears a model without files. Deleting the precision the model uses switches it to a copy still on disk, and the answer names it. Refused while a job uses it. Only on the user's request. | destructive |
| `arsenal_download` | `model`, `dtype?`, `allow_download?` | Downloads (or updates, or repairs) without running. | idempotent, open-world |
| `arsenal_load` | `model`, `dtype?`, `fast?`, `allow_download?`, `force?` | Loads, downloading first under the consent rule. | idempotent, open-world |
| `arsenal_unload` | `model` (or `all`) | Unloads; `all` keeps models a job is using. | idempotent |
| `arsenal_run` | `model`, `operation?`, `input`, `allow_download?`, `force?`, `play?`, `wait_seconds?` (default 25, max 45), `format?` | Runs an operation (default: the model's primary one), downloading and loading first when needed. | open-world |
| `arsenal_wait` | `job`, `timeout_s?` (default 50, max 3600), `format?` | Waits for a job and returns its result. | read-only |
| `arsenal_cancel` | `job` or `model` | Stops a job, or a model's download wherever it started. | destructive |
| `arsenal_upload` | `filename`, `data` | Stores base64 data (up to 700 KiB) in the inbox for agents whose file is not on this Mac. | — |
| `arsenal_settings` | `model?`, `set?`, `apply?`, `action?` (`refresh`, `approve_code`, `revoke_code`, `rollback`), `content_digest?` | Reads or changes settings. | — |
| `arsenal_playback` | `action` (`stop`, `mute`, `unmute`, `status`) | The shared speech queue. | — |

`arsenal_run` and `arsenal_wait` carry `_meta["anthropic/maxResultSizeChars"] = 500000`, so Claude Code keeps long transcripts in context instead of swapping them for a file reference. Arguments are validated against each tool's schema, then operation inputs against the model folder's schema, before anything runs.

## Consent

1. Arsenal never starts a download, a copy of local files that uses disk, an update or a dependency install unless the call carries `allow_download:true`. Without it, `run`, `load` and `download` answer (not as an error) with one line of facts and one of instructions: size, the time at this Mac's last measured rate (median of the last five Gets of at least 100 MB per source host, kept in `<support>/mcp-download-rates.json`; "time unknown until the download starts" without history), new dependencies, the RAM need against memory free now, and "Ask the user. With their yes, call … again with allow_download:true".
2. A Get that downloads, copies and converts nothing needs no consent: installed blobs, or local files that clone. The core Get plan decides clone or copy per donor file from the volume of its resolved path against the weight store (`localCloneBytes` on each plan item); copies from another volume ask and are disk-checked like downloads. Making an int8 or int4 tier from installed weights also asks, with its declared size, and is disk-checked. A download already running, in the app or over MCP, is joined without asking.
3. With the flag, Arsenal checks the Mac-fit bound and free disk (`[disk] Not started: needs …, … free on the startup disk.`) before any byte moves, starts one Get per model and dtype (a second call joins it) and answers within about 5 s, once the speed is measured: `Downloading X: 2.5 GB, about 4 min at 11 MB/s. … Job J.` The same job then loads and runs.
4. If the plan grew more than 10% over the size last reported for that model and dtype (within 24 h), Arsenal asks again with the new size instead of starting.
5. `force` concerns memory only. Neither flag implies the other, neither is saved, and `force` never overrides a model that cannot fit under the limit even with nothing else loaded (`[memory] Won't run on this Mac …`).
6. A local model whose code nobody approved neither downloads, loads nor runs (`[approval]`); `arsenal_settings(model, action:"approve_code")` approves its current digest (or the given `content_digest`) and is to be called only with the user's yes. After its code changes, the user's new yes is enough: no parity or speed evidence is asked for a local drop-in. `revoke_code` forgets the approval (unloading the model), so the next Get, Load or run asks again. In 1.0 Arsenal cannot tell an agent's call from the user's: any client holding the access token can call `approve_code` itself, and only the instruction to ask first stops it. Give the token only to agents you trust to ask, or approve code from the app's settings card yourself.
7. Elicitation is not used: the agent asks the user in context.
8. A gated Hugging Face model (its files need an account that accepted the owner's terms) answers `[waiting_on_person]`: what the user must do and where (the model's page; without a token also the token page and Settings › Hugging Face Token… in the app). Arsenal opens those pages in the default browser once per wait, retries every 30 s up to 10 times, and the next Get, Load or run (or the app's Get) retries at once. A token is read from Arsenal's Keychain item, then `HF_TOKEN`, then the Hugging Face CLI's token file; no tool or HTTP route sets one, and none is ever logged.

## Jobs, waiting and progress

`run`, `load` and `download` are app-owned jobs with 10-character ids. A run returns its result when it finishes inside `wait_seconds`; otherwise `Running X: step 12 of 28, about 40 s left. Job J — call arsenal_wait(job:"J").` `arsenal_wait` returns the result, or after `timeout_s` (default 50 s for every client, under Codex's 60 s tool timeout) `Still downloading X: 1.8 of 2.5 GB, about 1 min left. Call arsenal_wait(job:"J") again.` A client that moves long calls to the background (interactive Claude Code after 2 minutes) may pass a longer `timeout_s`; T3 threads, SDK sessions and subagents are not backgrounded and keep the default, so the agent is never held.

While a wait runs and the client sent a progress token, Arsenal sends `notifications/progress` at most every 5 s when something changed and at least every 20 s otherwise, so Claude Code's 5-minute idle abort never fires during a stalled download. `progress` strictly increases: it is the byte or step count when that is higher than the last value sent, else the last value plus one with no `total`; the figures are in `message`. Nothing is sent after the job ends.

ETA: download speed is bytes over the last 15 s of samples, shown after 3 s and 1 MB ("measuring speed" before); remaining time is remaining bytes over that speed, worded "under a minute", "about N min" or hours above 90 min; 30 s without new bytes reads "no data for …". Conversion after a download says "time not measured yet". Runs with steps estimate elapsed ÷ steps done × steps left; others report elapsed time.

Cancelling a wait leaves the job running; cancelling the initial `run`, `load` or `download` call cancels its job; `arsenal_cancel` stops a job or a model's download. Jobs share one Get per model and dtype and are counted on it: a cancelled job stops the Get only when MCP started it, no other job waits on it and the job was still downloading. A Get started in the app or over HTTP stops only with `arsenal_cancel(model:)`. A client that sends no progress token waits at most 50 s per call whatever `timeout_s` says, since nothing else keeps the stdio bridge's 60 s request alive. When more than 128 jobs exist the oldest finished ones leave memory; `arsenal_wait` on them returns the saved full result. A stopped download keeps its partial files and resumes. Jobs are recorded in `<support>/mcp-jobs.json` (terminal ones for 24 h): after a restart `arsenal_wait` answers `[failed] Job J (…) was interrupted by an Arsenal restart. Call the same tool again; a download resumes where it stopped.` or the finished job's first line and output path. `arsenal://jobs/{id}` exposes a live job as JSON.

## Results

Every result is text. Content is relayed in full and never trimmed; every text result is also saved to `<support>/jobs/<job folder>/output.txt`, and the header line names it when there is a body. Per output:

- Transcripts: header with audio length and the detected language by name (omitted when the model detected none, such as `und`), then the text; `[mm:ss.s–mm:ss.s] text` lines when timestamps were requested. Diarization: `[mm:ss.s–mm:ss.s] SPEAKER: text` lines.
- End of turn: one line. Embeddings: vectors written to `output.json`, `N vectors × D dims in <path>`, never inline. Rerank: ranked lines with document index, score and a snippet. Detection and screen grounding: one line per box or point with label and score. Translation: the text (numbered when several), with the detected source language by name when there is one. Documents: `Page N:` and its markdown; embedded images stay in `output.json`. Extraction: the extracted JSON, pretty-printed, as content. Decisions: `question: yes 0.77`, `choice 0.62` or `score 1.07 (confidence 0.57)` lines, one line per item for batches. Chat: the reply. Anything else: the output JSON as content.
- Files: `Created N images with ID (size, took T), seed S:` then one absolute path per line with pixel size or duration, format and size, plus a `resource_link` per file and a 256-px PNG thumbnail for images. Speech adds `Playing now.` or `Not played: playback is muted.`
- After a download inside the job, the first line is `Downloaded X (2.5 GB in 3 min 40 s).`

`format:"json"` (on `find`, `model`, `status`, `run`, `wait`) returns the data as `structuredContent` with the identical serialized JSON as text. Generated files stay in the job folders; `resources/read` serves an output link's bytes (64 MiB combined bound; up to 1,024 links registered, older links expire while the path stays usable).

## Errors

Failures are `isError:true` with one line starting with a category from a closed list, the reason and the next step: `[invalid_input]`, `[unknown_model]` (with the closest id), `[not_found]`, `[memory]`, `[disk]`, `[download]`, `[busy]`, `[cancelled]`, `[unsupported]`, `[approval]`, `[failed]`, `[limit]`, `[waiting_on_person]`. Memory refusals (`insufficient_memory`, HTTP 409) name the loaded models to unload, idle and largest first, and the force condition; the Mac-wide and runaway stops (HTTP 507) say what was unloaded. A failed download says how far it got and gives the resume call, unless a pinned file is not in its repository at the pinned revision: then no retry can succeed, and the line says not to call again. A refusal after a finished download (memory, for example) starts with `Downloaded X (2.5 GB in 4 min), kept on this Mac.` Malformed protocol requests remain JSON-RPC errors.

Before Load or the first operation on an unloaded model, Arsenal compares the chosen precision’s table peak memory (if absent, known Load peaks and the declared memory forecast provide a conservative fallback) with the room under the Mac-wide line now: the RAM the Mac can use without swap, less the RAM already above the line of 100/128 of its RAM (107.4 decimal GB on a 128 GB Mac, which the app shows as 100 GB of 128 GB). A Load that would take the Mac past that line is refused, which keeps the Mac out of swap; the Mac-wide guard below would otherwise stop it. A shortage returns `insufficient_memory` with HTTP status 409, `details.needed_gb`, `details.free_gb` (decimal GB, the room under the line), `details.limit_gb` and `details.total_gb` (decimal GB), model and precision, and a force hint. `details.idle_models` (`id`, `name`, `gb`) lists Arsenal's own loaded models that are idle (no request running or waiting, not Keep loaded), and `details.unloading_idle_fits` says whether unloading them makes room: then the refusal names them, the HTTP message gives the `POST /arsenal/v1/unload` calls, and the app's pop-up adds Unload Idle Models and Load beside Cancel and Load Anyway. Wire figures are decimal GB (10^9 bytes); the app shows Activity Monitor's GB (2^30 bytes), so 107.4 decimal GB reads as 100 GB. MCP's own answers, text and `format:"json"` alike, give memory in the app's GB (`limit_gb` 100). Cancel or unload other models; retry the same HTTP request or MCP tool with top-level `force:true` only after the user accepts macOS swap and its effect on the whole Mac. Force is request-scoped, never a saved preference, and does not bypass trust, missing assets or invalid inputs. HTTP clients can instead send `X-Arsenal-Force-Load: true`; this also works for multipart requests. For direct operation endpoints, `force` is transport metadata and is removed before model schema validation. An already loaded model needs no new load admission. Without a peak or declared forecast, loading proceeds with `loadMemoryNote` on the model row and a system-log diagnostic saying that fit could not be checked. Reload counts the outgoing worker’s released footprint and reserves the replacement before unloading; a genuine refusal keeps the resident. For replacement refusals, `free_gb` includes that release and `released_gb` identifies its contribution; the warning says that capacity is available after unloading. Recovery uses its captured revision’s evidence and at least its observed resident footprint. The native Load action shows a quiet line when the requirement is unknown. Legacy queue/swap preferences never suppress this warning or authorize swap for a load. A forced resident is exempt from automatic pressure eviction until it unloads; configured idle unloading still applies, and later Loads need their own force. Automatic recovery from a failed replacement preserves the previous resident’s consent, without authorizing the candidate or any later Load. Serving workers never stop for system swap growth alone. While any worker request runs (Load, operations, Get-time int8/int4 conversion, measurement and intake), Arsenal samples every half second the worker’s memory footprint and the whole Mac’s memory in use. When the Mac has more than 100/128 of its RAM in use, it stops one running worker: among those that grew by more than 512 MB during their current requests, the one furthest past its expected peak plus 1 GB (past where its requests started, when no peak is known). A worker that did not grow is never stopped for memory other apps took, and stops happen one at a time. Separately, a model with a measured request peak is stopped as a runaway at four times that peak and at least 16 GB above it, whatever the Mac’s state; a Load peak or forecast sets no per-worker bound. A forced resident takes no part in the Mac-wide stop; it is stopped only at twice its expected peak and at least 4 GB above it. The stopped request fails with `memory` (HTTP 507) once the worker has exited, with `details.reason` `mac_memory_limit` (`details.mac_in_use_gb`, `mac_limit_gb`, `start_gb`, `footprint_gb`, and `expected_gb` when known) or `runaway` (`details.footprint_gb`, `ceiling_gb`, `expected_gb`); the model unloads, and the stop does not count toward runner quarantine. Other strict memory and swap stops belong to lab/intake runs. Cache budgets and request validation remain active. Allocation errors and worker exits are reported as request failures without taking down Arsenal.

Texts state memory in the app's and Activity Monitor's GB (2^30 bytes) so they match what the user sees ("100 GB limit"); download and disk sizes are decimal, as in Finder; `format:"json"` keeps the decimal wire fields.

## Files

A `{"path": …}` anywhere in a run's input, and a path-type setting, may name any file on this Mac. Arsenal clones it (`fclonefileat`) into a fresh `<support>/inbox/<uuid>/` folder (mode 0600, pruned after 24 hours) and the model reads the clone; across volumes the job copies it first in a "copying" phase with progress. Files already in the inbox or a job folder are used in place, by their real path. Checks and clones run off the router actor and are refused after 10 s (a privacy prompt waiting for the user). Rules, because Arsenal may hold macOS privacy grants (Desktop, Documents, Downloads) that the calling process lacks, and reading a protected folder can raise a permission prompt: the file is opened with `O_NOFOLLOW` after resolving symlinks, judged by `fstat` and its real path (`F_GETPATH`); only regular files; no devices (`/dev`); nothing in Arsenal's own support folder outside inbox and jobs (token, configuration), hard links to them included, and no hard links inside inbox or jobs; a free-disk check before any copy that is not a clone; a clear `[invalid_input]` naming the privacy cause when the file cannot be read. `arsenal_upload` takes base64 data up to 700 KiB for agents whose file is elsewhere. The bearer token limits callers to local processes that can read the 0600 token file.

An object-typed input property whose schema declares `x-arsenal-ordered` (NuExtract's `template`, elephant-1's `questions`) may be sent as the JSON text of the object to keep its key order exactly; a plain object is accepted too, without that guarantee. An ordered property that may hold any JSON value (elephant-1's `state`, judge `items`) treats a string as text; to keep an object's key order, send the value plus `ordered_json: {"<name>": "<the same value as JSON text>"}`. Segmentation sessions belong to one loaded model; close them explicitly or unload. Live audio uses the HTTP Realtime WebSocket profile, not a long-held MCP call. Arsenal manages output folders; `out_dir` is refused.

## Playback

Speech (`speak`) plays aloud unless `play:false`; the file keeps the model's original level. Playback uses BS.1770 loudness and true peak measurement with one downward-only gain toward −16 LUFS and a −1 dBTP ceiling. `arsenal_playback(action:"stop"|"mute"|"unmute"|"status")` and `GET/POST /arsenal/v1/playback` control the shared queue. Muting pauses existing playback and skips newly generated clips; Stop clears the queue and prevents clips still being measured from entering later. Playback failures are reported in the result and keep the generated file. `ARSENAL_PLAYBACK_MUTED=1` starts isolated test instances without audible playback.

## Settings and extensions

`arsenal_settings(model:ID)` lists `dtype`, `keep_hot`, `show_in_menu`, `runner`, `fast` (chosen with `arsenal_load(fast:)`) and the folder's declared settings with value, range or choices and when they apply. `set:{…}` validates every reserved key first; the model's settings and Show in menu are one atomic write, then `dtype`, `keep_hot` and `runner` apply in that order, and a failure reports which keys applied. `apply:true` reloads so load settings take effect now. Without `model`: the app's `idle_unload_minutes`, `manual_idle_unload_minutes` and `when_full`; Launch at Login stays in the menu, the 100 GB limit is fixed, and the app does not update itself over MCP.

Drop model folders into `<support>/local-models/ID`, edit `<support>/config.json`, then `arsenal_settings(action:"refresh")`. The [folder contract](MODEL-FOLDER.md), [adding a model](ADDING-A-MODEL.md) and [runner protocol](RUNNERS.md) define how new models plug in. `rollback` returns a model to its previous revision. For adding an adapter without downloading weights, read `arsenal://integration/INTEGRATING.md`; declared models are in `arsenal://integration/MODELS.md`.
